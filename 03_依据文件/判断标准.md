# 内容判断标准 · 怎么判「好」和「不好」

> 这份文件和 `README.md` 分工不同：
> **README 管「怎么做出一份同版式报告」，本文件管「正文里的判断凭什么下」。**
>
> 版式错一眼能看出来，判断错没人看得出来——所以这份更要照着用。
> 所有条目都是从 37 组基线 + 画我组 + 子渝 48 组里实测出来的，不是行业通论。

---

## 一、价值传递：一条主张，三条硬标准，一条否决

### 1.1 一句话

> **好的价值传递，是让客户自己算出这笔钱花在哪；不是销售把产品讲得多全。**

判断时抓这个区别：
- 「讲得全」是销售侧动作，讲完客户回「行」「好的」——**没成**。
- 「算得清」是客户侧反应，讲完客户开始问「那学完能去哪」「9 个月线上怎么上」——**成了**。

### 1.2 三条硬标准（缺一即不达标，不打分、只打勾叉）

| # | 标准 | 回答客户心里的什么 | 怎么算达标（可核对） |
|---|---|---|---|
| 1 | **有形态** | 我买的是什么 | 3 个月线下 + 9 个月线上 + 两年复训，**三件套都出现过**，只讲「三个月」算 ✗ |
| 2 | **有出口** | 买完能得到什么 | 就业路径（去哪上班 / 谁推荐）、收入区间（底薪 / 课时费）、证书去向（谁发 / 什么用），**至少一条讲透**，只报名词不算 |
| 3 | **有落点** | 跟我有什么关系 | 至少一处挂到客户自己说过的话 / 自己的情况，**且客户下一句变具体或做出动作** |

第 3 条是唯一需要看客户反应的。只挂了一句「你本身有健身底子」然后继续念体系，客户回「行」——不算落点，那只是插了一句称呼。

**口径提醒（重要，别把初筛数当报告数）**

37 组基线上，人工逐组核出的结果是「三件套讲全 13/37、出口 12/37」。**同一批数据用词表机器初筛，实测算出 10/37 和 23–27/37**（出口词表越宽，虚高越多）。

差距来自两处：销售常把「9 个月」说成「线上课」不带数字；出口词表里的 `推荐` `门店` `面试` 在探需阶段就会命中，但那时还没讲出口。

所以规矩是：

| 数字怎么来 | 能不能写进报告 |
|---|---|
| 人工逐组看过原文 | ✅ 可以，写「逐组核」 |
| 词表初筛直接出的数 | ❌ 只能用来缩小人工要看的那几十条 |
| 同一份报告混用两种 | ❌ 绝对不行，读者会拿两个分母互相对 |

**写进报告的每个比例，都要能说清是「人工核」还是「脚本算」。** 说不清就不要写比例，写组数和那句原话。

### 1.3 一条否决（一票不达标，不看其他两项）

> **用优惠替代价值**：客户说贵，销售只改价格、不解释贵在哪。

判断方法：该组对话里「优惠 / 便宜 / 减 / 折 / 给你申请」类表述 ≥1 次，且全组没有一次讲清 21800 买到什么 → 直接判不达标，不管形态讲得多全。

实测：李雅雯 64 条销售消息，提价格/优惠 9 次，讲就业 0 次、讲收入 0 次，四天里客户说 4 次贵，一次都没解释。

### 1.4 四种失败型（做培训反面教材，比「不达标」更好懂）

| 类型 | 特征 | 一眼识别 | 实测实例 |
|---|---|---|---|
| **通稿式** | 讲得全，跟这个客户没关系 | 大段课程体系，客户全程只回「好的」 | 李雅雯 09:55 那段 273 字 |
| **资料包式** | 图片 / 语音 / 小程序代替解释 | 客户问一句，回 3 张图 + 4 秒语音 | 「有就业岗位推荐？」→ 语音+3 图 |
| **跳档式** | 跳过低价档，直接报最高档 | 客户问「普通证书」，直接 21800 | 李雅雯；3500 这个产品一直存在，全组 0 次报出 |
| **讨好式** | 客户说什么都「是的」「可以的」 | 客户抛错误认知，销售顺着答 | 「ACE 比国职更好咯」→「是的，是的」 |

**跳档式最贵。** 客户预算 2 万，听到 21800 就直接流失；而 3500 的单考证和 19300 的精英班都在货架上，从来没被摆出来过。

### 1.5 加分动作：先分叉，再报价

报价前先摆出两个以上方向让客户选，再按客户的选择解释——不是先报一个数再解释。

实测：子渝 32/48 组（67%）有这个动作，出口项达标率 40%，高于基线 32%。
反例：只报一个价、客户嫌贵后再降价，等于告诉客户「刚才那个价是虚的」。

### 1.6 好价值传递是**设计成两轮**的

```
第一轮：讲形态（3+9+复训），讲到「学完能上手」就停 —— 留一个缺口
   ↓ 客户自己问「那学完能去哪 / 好找工作吗」
第二轮：接住这个问题讲出口（就业路径 + 收入区间）
```

一轮讲完（形态+出口+证书全倒出来）就是通稿式。**缺口是设计出来的，不是忘了讲。**
判断"是否两轮"：看客户那句追问是不是销售问出来的——销售问「你想往哪方面发展」，客户答了再讲，也算两轮。

## 二、形态三件套：话术骨架（来自《招生老师参考话术》）

讲形态时三件都要出现，顺序固定 3 → 9 → 复训：

| 件 | 内容 | 必须带的一个具体数字 |
|---|---|---|
| **3 个月** | 线下全日制，半天理论半天实操，四个阶段，周一到周五，每天七节 | 班级 30–40 人，每阶段配专属带班老师 |
| **9 个月** | 毕业赠送线上配套视频，边工作边跟学，随时答疑 | 9 个月（不是"长期"） |
| **两年复训** | 入学两年内免费回校复训 1 次，薄弱板块针对补，不用重读 | 两年内 1 次 |

可拆可休学：学习能拆分、能办休学，后续跟下一期对应阶段继续。

**讲形态最容易漏的**：只讲 3 个月（基线 20/37 = 54% 只讲这一件）。因为 3 个月是客户问的那句，销售就只答那句。

## 三、出口：三条线，每条都有硬数字

### 3.1 就业路径

- 主要去向：商业健身房私教岗、高端私教工作室
- 自有品牌：健萌 **49 家**直营门店
- 合作：全国 **2000+** 健身品牌
- 承诺：每个毕业生**至少推荐 3 次**；毕业前**至少两周**一对一沟通；不合适可重新推荐
- 跟踪：毕业后跟踪 **1 年**（9 个月线上课就是服务已毕业学员）
- 口径红线：**是「推荐就业」，不是「包分配」**。说成包就业的直接判错，这是投诉源。

### 3.2 收入区间

- 结构：底薪 + 课时费 + 销售提成（部分门店有住房补贴、奖金）
- 底薪 **800–3000**，行业普遍 1000–2000
- 课时费 **40–80 元/节**
- 新人 1–3 个月过渡期，收入不高，积累会员后才涨

讲收入必须带区间和结构，只说「收入很高」等于没讲。

### 3.3 证书去向

- 毕业可得：红十字会 CPR 救护员证 + 6 本学院认证（肌力训练 / 减脂 / 营养学 / 训练规划 / 功能纠正 / 高级私教）+ 所选的 1 个官方资格证
- 含金量：ACE ＞ ACSM/NASM ＞ 新国职（「新国职是本科文凭，国际四大是研究生文凭」）
- 国职：国家体育总局人力资源开发中心发，考试理论+实操+体能，**只有 1 次机会**，近半年通过率 87%+
- NASM-CPT：美国运动医学会，**3 次**考试机会，首考通过率约 82%
- 一线城市门店可能要求国际证；普通门店国职够用

**红线**：不要说「证书最重要」。正确口径是「证书只是敲门砖，实战和会员服务能力更重要」。

## 四、价格阶梯（判断「跳档式」的唯一依据）

| 档位 | 价格 | 含什么 | 适合谁 |
|---|---|---|---|
| 单考证（单考国职） | **3500** | 4 天培训，只有 1 本证 | 只要证、不想系统学 |
| 精英认证班 | **19300** | 先学技术，不考证 | 预算紧、暂不做教练 |
| 新国职认证课程 | **21800** | 3 个月 + 国职考证 | 主流选择 |
| NASM-CPT | **24800** | 国际认证 | 一线城市 / 高端馆 |
| ACE-APT（国内版） | **24800** | 3 次考试机会 | 大陆与港澳台通用 |
| ACE-CPT（国际版） | **26200** | 2 次考试机会 | 国内 + 北美 |

**食宿另算**（学费不含）：

- 住宿：长沙 550/月（包水电）｜广州 750–850/月｜南京 750/月
- 伙食：食堂 10–20 元/餐，按 30 元/天 ≈ 3000/3 个月
- 典型总账：21800 + 1650（3 个月住宿）+ 3000（伙食）= **26450**
- **实际要交**：21800 + 1650 = 23450（伙食自己充），不住宿就是 21800

**保障**（报价时必须一起给，能显著降低决策压力）：

- 定金 **500**，不来可全额退，也可延期保留名额
- 入学 **10 天**内无理由退学费
- 两年内 **1 次**免费复训

**常见漏报**：只报 21800 不讲食宿，客户自己加出 26450 会觉得被套路（案例：客户「21000 突然加完就是 26000 了，我太难了」）。正确做法是主动拆开算，并说明「交钱只交 23450」。

## 五、六阶段：每阶段该做什么、最常见漏什么

| 阶段 | 该做的动作 | 最常见漏做 |
|---|---|---|
| S1 接通建联 | 自报身份 + 给出一个低压力下一步（发课程内容 / 约到校） | 一上来问预算 |
| S2 定级探需 | 训练基础 → 现状（在职/在读/待业）→ 是否想转行 → 时间能否脱产 | 只问「想了解什么」，不问时间能否脱产 |
| S3 价值传递 | 形态三件套 → 停 → 接客户追问讲出口 | 只讲 3 个月；或一轮全倒完 |
| S4 方案报价 | 先给选择（3500 / 19300 / 21800）→ 用问题筛选 → 锁定痛点再报价 | 跳档直接报 21800；报完不拆食宿 |
| S5 异议处理 | 先接住情绪 → 识别真正卡点（钱 / 家人 / 能力 / 城市）→ 再给方案 | 把「贵」一律当钱的问题，直接降价 |
| S6 逼单收口 | 给具体日期 + 具体动作（留班次、发定位、约到校时间） | 停在「那你考虑好联系我」 |

**S3 与 S4 的边界**：客户还没问价时讲形态=价值传递；客户已经问价、销售还在讲形态=答非所问。两者都要在报告里分开统计。

## 六、六层客户纵深（只看客户说了什么）

阶段是销售走到哪，纵深是**客户被推到哪**。做「价值传递有效性」必须用纵深，不能用阶段——阶段会把「销售讲了一堆」算成推进。

| 层 | 定义 | 判定词（客户原话） |
|---|---|---|
| **L1** | 只有实质回应 | 嗯 / 好的 / 行 / 在的 / 谢谢（有内容但没推进） |
| **L2** | 问到证书或课程 | 什么证 / 课程 / 学什么 / 几个月 / 怎么上 |
| **L3** | 交出自身信息 | 我在上班 / 刚毕业 / 自己练 / 想转行 / 预算 X |
| **L4** | 下探出口 | 就业 / 好找 / 分配 / 推荐 / 工资 / 收入 / 薪资 / 前景 / 能去哪 |
| **L5** | 问到班期或价格 | 多少钱 / 学费 / 什么时候开班 / 几号 |
| **L6** | 做出动作 | 定金 / 转账 / 我过来 / 帮我定 / 发定位 |

**定级三原则**：
1. 只升不降，取最高层。
2. 只认客户说的，销售问「你想找工作吗」不算 L4。
3. **「回答现职」不算 L4**。客户答「在上班」是在答 S2 的探需，不是问就业。L4 只认客户主动问出口。

> 踩过的坑：最初用 `工作|上班` 匹配 L4，把「我在上班」当成问就业，多算 1 组（38→37）。已收紧为 `就业|好找|分配|推荐|工资|收入|薪资|前景|能去哪`。

**怎么定级（逐组人工，三步，一组 30 秒）**

1. 先把客户消息全捞出来，**跳过「嗯/好的/行/谢谢/在的/[表情]」这类纯回应**。
2. 剩下的从后往前看，找到**最高那一层**：能做动作（定金/我过来/发定位）→ L6；问价/问班期 → L5；问就业收入 → L4；说自己的情况 → L3；问课程证书 → L2；只剩纯回应 → L1。
3. 同一组里客户先问价、后问就业，取 L4（高者），不取 L5。

**口径提醒**：这套层级的数字是**逐组人工核**的，不是脚本算的。48 组子渝数据实测：「人工核 42→37→34→30→29→5」，直接拿上表的词表跑会得到另一组数（L2 只出 13/48，因为客户问「住宿怎么样」「有年龄限制吗」也算 L2，词表接不住）。
**报告里写纵深，必须人工核一遍；词表只用来把可疑的组挑出来。**

**断点看哪里**：算出各层累计人数，找掉得最狠的那一跳。
- 37 组基线：36 → 36 → 35 → 28 → 11 → 7，断在 L4→L5（28→11），即**报价后大量不回应**。
- 子渝 48 组：42 → 37 → 34 → 30 → 29 → 5，断在 L5→L6（29→5），即**问了价但不下单**。

断点位置不同，结论完全不同：前者是报价方式问题，后者是收口问题。**不要套用上一批的结论。**

## 七、容易判错的地方（都是实际踩过的）

1. **「在上班」不等于问就业**（见上）。
2. **客户先问价不等于价格敏感**。要看他问的是「多少钱」还是「有没有便宜的」。前者是正常比价，后者才是预算卡点。
3. **优惠词多不等于客户嫌贵**。子渝全盘优惠类词 130 次，客户主动喊贵只有 6 次——大部分优惠是销售自己先给的。
4. **追问同一件事算 1 次**。客户连问三句「多少钱」是一条诉求，不能算 3 次。
5. **不要用「某句话很打动人」当证据**。必须有客户侧的下一句作证：变具体了、问到细节了、做出动作了。三条都没有，就是销售自我感动。
6. **跨天拼接要标时间差**。同一结论如果隔了 3 天才给，结论就不是「做得对」，而是「动作对、节奏慢」。这类判断错得最隐蔽。
7. **单组数据不要讲比例**。1 组只讲事实和次数；说「100% 的客户」没有意义。
8. **引号不是修辞，是「这句在图里」的承诺**。正文写「客户回了：那就差不多 3 万块」，读者会去右侧截图找这句；找不到，这一整张卡就不可信了。所以：引号内只能是原话（截断可以，改写不行），且必须落在同一张卡的截图区间内；概念性说法（「你的产品矩阵长什么样」「他不想被通知一个总数」）不加引号，改用加粗。
9. **引号外不等于可以自由发挥**。2026-11-09 片段六写过一句「他说清了它不擅长什么（运动科学这块讲得相对浅一点）」——没加引号，`check_quotes.py` 只核「」，一路绿灯；可完达山那组 113 条消息里从没出现过「运动科学」。这句话是从行业常识补出来的，属于**编造**，比抄错严重一个量级：它读起来像事实。
   - 判断标准：**引号外只要出现具体信息，就必须能落到原文**。具体信息 = 数字（金额/条数/字数）、时间（哪天几点）、名词（证书名/品牌名/校区名/课程模块名）、以及**括号和破折号后面那半句**。
   - 括号是重灾区。括号天然被当成「具体说明」的位置，写的人容易顺手补一个自己知道、但客户没说过的事。写完自问：这半句的原话在哪一条消息里？答不上来就删。
   - `check.py` 第 12 项（`audit_claims.py`）核四类：金额、日期、时间点、外文词；外加括号补语的用词出处。它查不出的（中文定性描述），只能靠人：把每句「他说了什么」拆成关键词，在原始 xlsx 里搜一遍，搜不到就改写。
10. **别组的数字不能搬进这组的卡片**。片段一写「用的是客户所在地的真实价格（长沙宿舍 550／月，广州是 750／850）」——550 是七顿自己的消息里有的，750／850 是李雅雯（广州）那边的价格，跟七顿这组无关。数字本身是真的，但放错位置，读者一核就露。**每张卡片里的数字，只能是这张卡片的客户说过的那几个。**

## 八、写文案时的口径红线

| 不许写 | 因为 | 改写 |
|---|---|---|
| 「53% 流失在报价层」 | 来源无法复现 | 写明分母：17/37 = 46%，或 17/28 = 61% |
| 「报价前问清三类信息占 43%」 | 43% 对应的是 `pre_ask ≥ 2`（两类） | 「问清两类以上 = 43%」；三类以上只有 4/28 = 14% |
| 「9 位客户一个下午收到」 | 未逐条核 | 核到具体时间窗和组数再说（实为 11.2 14:42–17:05 共 8 组） |
| 「包就业」 | 口径错误，会招投诉 | 「推荐就业，至少推荐 3 次」 |
| 「22:21 当晚给了结论」 | 把当晚发的资料误当成结论 | 查准那条消息的时间再写 |
| 「客户回了：那就差不多 3 万块」 | 这句在原文第 203 条，截图停在 201 条 | 把截图 `--end` 扩到那句，或删掉这半句——`check.py` 第 10 项会拦 |
| 「500 订金膨胀 2000」 | 概括，不是原话 | 抄原文：「500元订金，新国职和ACE，可以膨胀到2000元」 |
| 「（运动科学这块讲得相对浅一点）」 | 完达山 113 条里没有这句，是从行业常识补的 | 删掉；或改成他真说过的（「四大认证里全球持证人数最多」） |
| 「广州是 750／850」写在七顿的卡片里 | 750／850 是李雅雯那组的广州价格，不属于七顿 | 只用本组数字：宿舍 550／月、吃饭 1000／月、停车 150／月 |

**凡是写进报告的百分比，分母必须能在同一份数据里数出来。** 数不出来就写绝对数。

## 九、机器能算 vs 必须人看

| 项 | 能自动 | 说明 |
|---|---|---|
| 形态三件套出现与否 | ⚠️ 只能初筛 | 关键词：`三个月\|3\s*个月`、`9\s*个月\|九个月`（+`线上`）、`两年\|2\s*年`+`复训\|回校`。销售常把「9 个月」说成「线上课」，会漏 |
| 出口出现与否 | ⚠️ 只能初筛 | 就业词表、收入词表分开计；`推荐` `门店` `面试` 在探需阶段就命中，会虚高 |
| 价格档位报出情况 | ✅ | 3500 / 19300 / 21800 / 24800 / 26200 + 优惠词；数字是硬匹配，可靠 |
| 六层纵深 | ⚠️ 人工核 + 词表辅助 | 词表定级会偏低，见 §6 口径提醒 |
| 引号外的金额 / 日期 / 时间点 / 外文词 | ✅ | `audit_claims.py`：逐句比对，本次 35 张卡片 0 处错 |
| 引号外的中文定性描述（「他说清了…」） | ⚠️ 只能初筛 | 括号补语用词不在本组原文会报出来；其余靠人逐句搜关键词 |
| 客户是否先问价 | ✅ | 首次价格词 vs 首次主动报价，比时间戳 |
| **落点是否成立** | ❌ | 要看客户下一句是不是变具体，必须人看 |
| **正文引语能否在截图上找到** | ✅ | `check_quotes.py`（`check.py` 第 10 项）：靠 `shot.py` 的同名 `.json` 侧写逐条比对，200 处引语一次核完 |
| **四种失败型归类** | ⚠️ | 资料包式可机器初筛（同条含 2 图以上或语音），最终人定 |
| **是否两轮** | ❌ | 要看客户的追问是不是销售递出去的 |
| **异议是否真被处理** | ❌ | 「贵」的背后是钱 / 家人 / 能力，机器分不出 |
| **片段库漏斗的四个数** | ✅ | `audit_good.py`（`check.py` 第 13 项）：48 / 31 / 20 全部复算，6 是人工挑；数字与标签对不上就 ✗ |

**结论**：脚本负责把 3000 条缩到 30 条给人看，比例和定级由人下。报告里凡是判过的，都要能点到那句原话。

## 十、片段库（PART 04）怎么挑

这是唯一「不判错、只立标杆」的板块，所以标准跟前面九节是**两套**，别混：

| | §1.2 三条硬标准 | 本节三条入选标准 |
|---|---|---|
| 判什么 | 一整组 / 一整段的价值传递达不达标 | 某一个动作做对了没有 |
| 看链路 | 形态 → 出口 → 落点，要串起来 | 只看这一处，允许整组最后流失 |
| 结论 | 达标 / 不达标 / 一票否决 | 入选 / 不入选 |

所以会出现这种情况：片段三（3500 这档）整组最后卡在时间上没成交、片段六（ACE 品牌名）客户只回「明白了」——它们仍然进片段库，因为**单个动作成立**。反过来，讲得再全但客户只回「好的」，一句都不进。

### 10.1 三条入选标准（人工，逐段过）

| # | 标准 | 怎么算过 | 怎么算不过 |
|---|---|---|---|
| ① | **客户下一句变具体，或做出了动作** | 紧接的那条客户消息从「了解一下 / 看看」变成具体问题（问地点、问几天、问难不难），或直接给动作（「系统培训后考」「我下午过去」「定金怎么交」） | 客户只回「好的」「行」「明白了」「等我看看」——效果分为零 |
| ② | **换一个人也能照着说** | 把客户名和这一人的经历替换掉，这句话仍然成立 | 句子里带「你上次说…」「你姐在新西兰」这类只对这人成立的前提 |
| ③ | **不依赖特例** | 前提是所有人都有的（要上班、预算有限、零基础） | 靠不可复制的前提成立：亲属在国外、单位报销、内部名额、刚好认识店长 |

**三条不必全过，但过了哪几条要写清楚。** 只过②③的（客户没接住），必须在同一张卡里写出①没达成的证据——2026-11-09 片段六就是这种：话术是这批里唯一把证书讲成可核实事实的一段，但客户只回了「明白了」，当天下午才说「好的，等我看看」。卡片里同时写「证书讲清了，时间没接住」。

**不许因为「这段讲得漂亮」让它过①。** ①是唯一看客户反应的，也是「标杆」和「读后感」的分界线。

### 10.2 漏斗四步（数字必须可复算）

页面上那个 `48 → 31 → 20 → 6`，前三步是口径计数、第四步是人工挑。口径写在 `audit_good.py`：

| 步 | 口径（脚本里的正则） | 本批 |
|---|---|---|
| ① 全部通读 | 清洗后的会话组数 | 48 |
| ② 客户主动问过价 | 客户侧消息命中 `多少钱 / 费用 / 价格 / 学费 / 收费 / 报价 / 多少 / 贵` | 31 |
| ③ 报了数字且讲了形态或出口 | 销售侧有明确金额，且（`三个月` + `线上/九个月/复训/四个阶段` 之一）或（就业/收入/证书去向之一） | 20（其中形态两件以上 15） |
| ④ 人工入选 | 三条标准过两条以上，且有对照段可写 | 6 |

**标签必须跟口径一致。** 2026-11-09 出过一次：页面上写「15 组讲清了形态和出口」，实际 15 是「报了数字且形态两件以上」的组数，出口根本不在这个口径里；第二步写「问过价或课程」，数字却只是问价（并集是 33）。`check.py` 第 13 项现在会拦这种对不上。

### 10.3 每段卡片的固定五块

`发生了什么 → 做了哪几件事 → 为什么有效 → 同一场景没这么做的那组 → 可以直接抄走的原话`

- **第四块（对照组）不能省。** 没有对照组就不是标杆，是夸奖。对照组要能从「（见 PART 02 · Px）」跳过去核。
- **第五块只能是原话。** 抄的是他说过的句子，不是我们替他总结的方法论；改写过的就去掉引号（见 §八）。
- **一处细节对应一个动作。** 「做了哪几件事」里每条都要在「发生了什么」里有对应的那句原文，否则就是事后归纳。

### 10.4 不能进片段库的四种

| 类型 | 长什么样 | 为什么不行 |
|---|---|---|
| 形容词型 | 「四大里最全面的」「非常权威」 | 没有可核对的信息，客户无法验证，也没法照抄 |
| 单口型 | 销售讲了 300 字，客户全程「好的」 | 内容分够，效果分为零（通稿式的另一种） |
| 群发型 | 同一段话在 3 组以上逐字出现 | 照抄它等于照抄通稿，见 PART 02 · P2 |
| 特例型 | 靠「他姐在新西兰」「单位报销」成立 | 换个客户就不成立，不可复制 |

## 十一、CRM ID 与意向级别怎么接（案例头那串标识）

案例头固定三样东西：**客户昵称 → 线索 ID → 意向级别**。前两样证明「这个人是 CRM 里的哪一条」，第三样是销售自己在 CRM 里给这个人的判断。三样都来自线索导出表，不许手写、不许估。

### 11.1 标识长什么样

```html
<span class="case-who">销售全名 → <b>客户昵称</b></span>
<span class="cid" title="线索 ID 165541 ｜ 落入 2026-11-02 ｜ 来源 官抖-短视频（广州）">165541</span>
<span class="lvl" data-lv="C" title="意向级别 ｜ 1个月内未转化">C-意向较弱</span>
```

| 元素 | 什么时候用 | 注意 |
|---|---|---|
| `.cid` | 匹配上线索表 | 只写数字 ID，不要写「线索 ID 165541」占位；完整出处放 `title` |
| `.cid.warn` | 匹配上了但姓名对不齐（昵称改了、线索表记的是备注） | 虚线框，提醒读者这条要人工确认；`title` 里写明线索表的原始姓名 |
| `.cid.none` | 没匹配上 | 文本固定写「无 CRM ID」，**不要为了填满而硬塞一个 ID** |
| `.lvl` | 线索表有「意向级别」字段 | `data-lv` 必须等于级别文字的首字母（A/B/C/D），否则颜色和文字会对不上 |

颜色由 `data-lv` 决定：A 绿 / B 蓝 / C 米 / D 红。CSS 在 `style.css` 里（`.lvl[data-lv="A"]` 那四条），**不要另写行内样式**。

### 11.2 匹配顺序（先严后宽）

| 步 | 规则 | 例 |
|---|---|---|
| 1 | 人工别名表 | `波波📣工作版 → 波波`、`（杜康）问剑白玉京 → 问剑白玉京` |
| 2 | 姓名归一化后精确相等（去空格 / 全半角 / 标点，英文转大写） | `李二狗，→李二狗` 靠这条不行，得走第 1 步 |
| 3 | 微信列精确相等 | 昵称对不上但微信号对得上时兜底 |
| 4 | 姓名互相包含且**唯一**命中 | `铸山-《减脂版》→铸山` |

**单字昵称不参与第 4 步。** 「W」「1」「Y」这种，模糊匹配十个里有九个是错的人。匹配不上就写「无 CRM ID」，读者知道这一步没做到，比给一个错的 ID 强——**ID 是给读者点开 CRM 核对的，认错等于把人带到另一个人身上。**

### 11.3 意向级别的三个用法

1. **看落差**：报告说他「价值没传递到位」，CRM 里却是 B-意向明确 —— 说明话术把人吊住了，不是没人要。这类组最值得复盘。
2. **看流失**：C-意向较弱 + 7 日内未转化，且客户最后一句是「我再看看」，比销售自述的「他觉得贵」可信。
3. **不许当结论**：意向级别是销售自己打的，不是客户行为。它只能用来**对照**报告里的过程判断，不能替代过程判断——「他是 A 类所以谈得好」这种话不许写进正文。

### 11.4 三个坑

| 坑 | 后果 | 怎么办 |
|---|---|---|
| 线索表的「姓名」其实是微信昵称 | 拿真名去匹配，一个都对不上 | 先打印前 20 行看一眼字段长什么样 |
| 同一昵称多条线索 | 匹配到旧的那条，意向级别是三个月前的 | 优先取最新「线索落入日期」；拿不准用 `.cid.warn` |
| 导出表的 ID 是线索 ID，不是学员 ID | 和成交数据对不上 | 报告只写「线索 ID」，别写成「学员 ID / 客户编号」 |

### 11.5 落地：一条命令

```bash
python match_crm.py --xlsx "线索信息导出-20261109141615.xlsx" --html ../index.html \
    --overrides overrides.json --warn W --csv 02_过程文件/crm_map.csv --dry
```

- `--dry` 先看匹配结果，确认没认错人再去掉它写回。
- `--warn` 后面的昵称用虚线框标出，留给人工确认。
- `--csv` 导出对照表（昵称 / ID / 级别 / 匹配方式 / 落入日期），报告目录里留一份，读者能自查。
- 脚本是幂等的：重跑会先拆掉上轮写入的标签再重算，不会叠加。
- 跑完必须再跑一次 `check.py`，第 14 项会核「ID 有没有 title」「意向标签的颜色和文字对不对得上」「页面上每个 ID 在 crm_map.csv 里能不能查到」。

## 十二、截图必须点得开、缩得动（灯箱三件套）

报告里每张聊天截图都要能点开看原尺寸，点开之后**滚轮缩放、按住拖动、双击复位、Esc 关闭**。这不是锦上添花：报告里的判断都要靠截图逐字核对，图看不清就等于没证据。

### 12.1 页面里必须有的四个东西

| 东西 | 写在哪 | 少了会怎样 |
|---|---|---|
| `data-zoom="..."` | 包住每张 `<img>` 的那层 div | 点了没有任何反应，也不报错 |
| `<div class="lb" id="lb">` | `</body>` 前 | **整页图片都点不开**——`app.js` 里 `if (lb && lbImg)` 直接跳过整段 |
| `<img id="lbImg">` | 同上，灯箱里的那张大图 | 同上 |
| `<div class="lb-cap" id="lbCap">` | 同上，底部图注 | 图注不显示 |
| `<script src="assets/app.js?v=N"></script>` | `</body>` 前 | 同上 |

```html
<div class="qcard-shot"><div class="inner">
  <div data-zoom="V-1 就业流程讲透 ｜ 长生｜10.10 20:09"><img src="assets/value/v1.png" alt="V-1" loading="lazy"></div>
  <div class="qshot-cap">V-1 原文截图，点击放大</div>
</div></div>
```

`data-zoom` 里写「编号 + 这段在讲什么 + 客户名 + 时间」，它同时是灯箱的图注——读者放大后看到的不该只是一串编号。

### 12.2 为什么单独生成的页面最容易漏

主报告走 `骨架.html`，灯箱三件套是现成的；**另开的专项页（价值传递这种）如果是自己拼 HTML，很容易只写 `data-zoom` 和 `<script>`，忘了那三行 div**。这个漏法特别隐蔽：页面不报错、控制台不报错、图片照常显示，只是点了没反应——不逐页点一遍根本发现不了。

### 12.3 自查

- `check.py` 第 15 项：正文图数 vs `data-zoom` 数、灯箱三个节点在不在、`app.js` 里 `wheel` / `pointerdown` / `zoomAt` 还在不在。
- 手工验：随便点一张图 → 滚轮放大看百分比有没有变 → 按住拖 → 双击 → Esc。

## 十三、三项组合怎么读（决定先练哪一项）

单项达标率只回答「哪一项最弱」，回答不了「先练哪个」。要安排训练，得把三项**做组合**看：哪些短板是绑在一起出现的，哪些是单独出现的。

### 13.1 怎么算

三项各判「达标 / 未达标」，做 2×2×2 = 八格，把每一组客户放进它那一格，八格相加必须等于分母。这是纯算术，可以让人拿计算器复核。

```
形态 = 三件套齐？   出口 = 至少一条讲透？   落点 = 客户下一句变具体？
        ↓                    ↓                     ↓
     八格分布：11 / 7 / 6 / 5 / 5 / 4 / 3 / 0   （合计 41）
```

### 13.2 八格的含义

| 组合 | 名称 | 这一类人的真实问题 | 训练动作 |
|---|---|---|---|
| 形✓ 出✓ 落✓ | 三项全过 | 没有（除非踩否决） | 当标杆，别动 |
| 形✓ 出✓ 落✗ | 缺落点 | 产品讲全了，但没挂到客户身上 | 练「讲之前先复述客户上一句」 |
| 形✗ 出✓ 落✓ | 缺形态 | 接得住人、给得出路，就是讲不清产品结构 | 给一页纸的产品结构，最好练 |
| 形✓ 出✗ 落✓ | 缺出口 | 极罕见（本批 0 组） | 补一句「学完能去哪、能拿多少」 |
| 形✓ 出✗ 落✗ | 只有形态 | 在念产品，没在谈客户 | 先练听，别急着补出口 |
| 形✗ 出✓ 落✗ | 只有出口 | 报价 + 包就业/包考证，说完就停 | 出口讲之前先问一句客户想做什么 |
| 形✗ 出✗ 落✓ | 只有落点 | 客户被听懂了，却不知道路怎么走 | 补出口，最可惜的一类 |
| 形✗ 出✗ 落✗ | 三项全无 | 还没进入价值传递 | 先解决「有没有在谈这个产品」 |

### 13.3 三条读法（都是这次真碰到的）

**① 某一格是 0，要解释它为什么是 0，不能只把它当好看。**
本批「缺出口」是 0 组：形态讲到三件的 12 组里，8 组顺手把出口带上了（清单里自带「包就业」「两年复训」），剩下 4 组是贴完清单就停、出口和落点一起缺。所以「出口好、只差挂客户」这种理想状态根本不存在——这一条要写进报告，否则读者会以为是漏统计。

**② 看分布是「渐变」还是「断裂」。**
本批形态件数：1 件 27 组、2 件 1 组、3 件 12 组，中间的 2 件几乎是空的。这说明它不是「讲多讲少」的能力差，而是**手里有没有那份现成清单**——有就贴全套，没有就只说一句。判据：如果中间档（2 件）极少，问题在物料，不在话术；如果中间档很多，才是话术讲不全。

**③ 算一下两项之间的相关，别看单项率就下结论。**
本批形态三件的 12 组里落点只有 3 组成立（25%），形态不到三件的 29 组里落点成立 12 组（41%）——**讲产品讲得最全的那批人，落点反而最差**。这条只能当相关看，不能推因果；但复盘到具体组时原因很清楚：念得越完整，越像在输出，越不会停下来听。**如果出现这种负相关，补形态的教法必须改成「按客户情况拆」，不能是「背完整三件套」，否则越练越糟。**

### 13.4 训练排序的判断规则

不要按「缺得最多」排，按下面三条排：

| 序 | 判据 | 本批结果 |
|---|---|---|
| P0 | **哪一项是其他项生效的前提** | 落点（缺 26 组）。出口讲得再细，不挂到人身上，客户只回「考虑一下」——To 组就是出口 2 条、59 轮、落点为零，问完价消失 |
| P1 | **哪一项补上后「补一项就全过」的组最多** | 形态（缺 29 组，其中 7 组补上即全过：ZMBT、杜康、R、七顿、EAST、吕志勇、依依）。这是刷「三项全过」数量最快的，但**不等于提转化** |
| P2 | **哪一项模板化程度最高、最不依赖人** | 出口（缺 15 组）。可以标准化成一页纸，但优先级最低 |

配套要单拎出来的一类：**「只有落点」那 5 组**（客户被听懂了但一条出路都没给）。这类数量不多，转化损失最大，值得单独讲一次。

## 十四、三批怎么合（先查重，再合并，最后标出来）

拿到第二批、第三批导出时有两个放法，**都能用，但不能混**：

| 放法 | 什么时候用 | 结果 |
|---|---|---|
| **并列** | 想比「个人风格」——同一项谁的做法差在哪 | 两张表并排，各自分母，不排名 |
| **合并** | 想要「岗位级的结论」——哪一项是所有人都缺的 | 一张总盘，同一分母，加员工列 |

判断依据只有一条：**你要回答的是「谁做得好」，还是「这一项是不是共性缺口」。**

有一种情况必须合并：**老板圈了几组「这几个我盯着」，同时又要一份整体结论。** 这时候不要再开一节「重点四组」——四个活线索被供在旁边，读者会跳过它；并进正表、用底色标出来，它们才会被真正看见。这一版是这么做的：子渝 41 + 陈舒 55 + 点名 4 组 → **99 组**。

### 14.1 合并第一步是查重，不是拼接

同一批人可能被导出两次。**同一个客户、同一段时间、消息逐条相同的，只能算一组。**

这一版就撞上了：重点四组里的「姜彦博」，和之前那份陈舒导出里的是同一份会话——96 条消息逐条相同，只是员工备注名一个写「陈舒-pearrrr」、一个写「陈舒-？」。如果直接拼接，分母会虚增到 100，而且这一组会被判两次。

查重的做法（`merge_value.py` 里写死了）：

```python
DUP_IN_POOL = {"姜彦博"}   # 与前一批同一份会话，只算一组
```

**怎么确认是同一份会话**：比对 `n`、`start`、`end` 三个字段，再比 `msgs` 是否逐条相等——名字一样不算证据，两批里同名不同人的情况同样存在。

### 14.2 合并不等于「挑一个对自己有利的判读」

同一组被两批分别判过，结论可能不一致。这一版姜彦博就是：陈舒批记 `f3/o1/l0`（缺落点），重点批逐句读过记 `f3/o3/l1`（三项全过）。

规则：**以证据更细的那一版为准，并且把改动写进 note。**

- 不许「哪版好看用哪版」——那叫调数据；
- 不许悄悄改——`value_all.json` 的 note 里要留下依据（这一版写的是「出口讲成时间线（课程设置→推荐→回访）；落点接住『看就业怎么样』」）；
- 改完必须能回答一句：**为什么这版更可信**（答：重点批是逐句全读，陈舒批按价值段判读，漏掉了 87 行那段就业时间线）。

### 14.3 每批都要有自己的分层链

任何一批导出都不能直接进分母。按顺序剔，并把每一步的数字写在页面上：

| 层 | 判据 | 陈舒批 | 子渝批 | 重点批 |
|---|---|---|---|---|
| 内部 / 客服 | 昵称是员工名、客服名、内部群 | 6 | — | — |
| 已报名学员 | 昵称带班期编号或「学员」 | 5 | — | — |
| 无实质对话 | 客户不足 3 句，或总消息不足 10 条 | 25 | — | — |
| 未进价值场景 | 双方都没提课程 / 价格 / 就业 / 报名 | 14 | — | — |
| 只问 WiFi 与密码 / 客户 0 条 | 无招生内容 | — | 7 | — |
| **进入价值场景** | 其余 | **55** | **41** | **4（去重后 3）** |

三条链写清楚（`105 → 55`、`48 → 41`、`4 → 3`），`99` 这个数才站得住。合计 157 组导出，58 组没进入价值传递。

### 14.4 精度声明不能省

各批判读密度往往不一样（一批逐句全读、一批按价值段判读）。合并之后这句话必须写在页面上，否则读者会把 99 当成 99 份同精度抽样：

> 合并发生在**计数**这一层，不在**证据**这一层。比例与结构可靠；不能当成同精度抽样。

### 14.5 合并后的表：员工列 + 批次分组行 + 底色

- **员工列**：写清这组是谁的（不是「第几批」）。邓杰均、小威、路梦丽各自的名字必须出现，否则读者会以为是子渝做的。
- **批次分组行**：按「子渝批 / 陈舒批 / 重点批」插入分组行，长表才读得下去。**不要按员工分**——三个新老师各一组，会切出三段只有一行的分组，反而更乱。
- **不许排序打散**：一旦按达标情况排序，批次信息就没了。
- **点名的那几组用底色标**，见 §十五。

`audit_value.py` 会逐行核对员工列、并核对「琥珀底的行 == 数据里 focus=1 的行」——这两条别靠人眼。

### 14.6 合并之后能多看出三件事

如果这三条读不出来，就不该合并：

1. **共性缺口**：第一大类是「缺落点」20 组（20%），三批都在这一格，说明是岗位缺口不是个人问题。
2. **各有各的重格**：子渝最重「只有出口」11 组，陈舒最重「缺落点」15 组——同一个口径，落到做法上是两种补法。
3. **同一项的比例差**：形态 29% 对 67%（差一倍）、出口 63% 对 62%（几乎一样）。**差一倍的项是「有没有那句现成的话」，一样的项是「谁都会背」**。

## 十五、点名的几组并进正表之后，怎么标

### 15.1 只靠颜色，不开专节

并进正表之后就不能再有「重点四组」这一节——**一旦单开一节，读者会把它当成附录跳过**。识别靠三处颜色，够用且不打断阅读：

| 标在哪 | 怎么标 | 为什么 |
|---|---|---|
| 逐组表整行 | 行底色 `#FDF6E3` + 首格左侧 3px 琥珀内阴影 + 结论列一枚「重点」徽章 | 表是查证入口，颜色必须在表里 |
| 卡片 | `qcard focus`（琥珀卡号 + 琥珀边框）+ 极浅琥珀底 + 卡头「重点」标签 | 单独转发出去时标识还在 |
| 页面图例 | 口径那节一句 `focus-bar`：「凡琥珀底的就是你点名的四组」 | 颜色必须有说明，否则没人知道琥珀是什么意思 |

**不标分数、不排名次、不改分母。** 它们和其余组是同一个池子：分母 99 里就有它们，比例算的就是它们。

### 15.2 并进来要付的代价：一句声明

这四组是**点名挑的，不是随机抽样**。四组只占 99 组的 4%，对比例的影响很小，但这句必须写在页面上：

> 点名的那四组已并入同一个分母，不做单独的比率解读——它们是「要动手的线索」，不是「样本的代表」。

反过来，如果点名的是二十组、三十组，比例就会被挑选动作带偏，那时候宁可不并、只并列。

### 15.3 「下一步」照样要写，而且和其他块分开排版

`qblock qnext`（深蓝底 + 左侧竖线）。一条合格的下一步是**明天能照着发出去的一段话**：

1. **指名到动作**：写「发温州、杭州两地私教招聘截图（带薪资）」，不写「加强出口讲解」。
2. **接回客户说过的词**：每条都引用客户的原话或原数字（城市、年龄、体重、时间点）。
3. **不超过四条**：超过四条，执行的人会一条都不做。
4. **第一条要是「别再做什么」**（当这组已经触达失败时）：先止损，再谈加法。

**排版上要和「卡在哪」分开**：建议是动词，诊断是名词，混在一起读者只记得问题。

**引号规矩**：`qnext` 里的引号写的是**建议话术**，不是原文。所以一律用『』，不用「」。`check_quotes.py` 只认「」，这样建议话术不会被判成「原文里查无此句」——这一版就是踩过这个坑之后改的。

### 15.4 四组落在四格，本身就是结论

这一版四组判完正好是：三项全过 1、只有出口 1、只有落点 1、只有形态 1。**四格不重样**这个分布，比任何单组分数都有用——它说明「缺一项」在真实线索里是均匀发生的，不是某一类人特别多。所以这四组适合当**教练素材**：一组一个病，逐个对着改。

反过来说，如果四组里三组都缺落点，那结论就不是「四个人各缺一格」，而是「落点是这批人的共同盲区，值得开一次专项」——**分布决定动作，不要预设**。

### 15.5 四张卡必须能寻源

并进正表之后，这四张卡和别的卡**没有区别**：一样要有截图、一样要能逐字反查。

- 出图：`mk_focus_shots.py`，一次把四组的十几段都配好，自动写同名 `.json` 侧写；
- 截图段落怎么选：**每一句要引的原话，都得在选中的段里**。先列引语，再定段落，别反过来；
- 卡里如果引了别组做对照（`qopp` 块），`check_quotes.py` 会跳过——那是另一位客户，不该拿本卡图核。
