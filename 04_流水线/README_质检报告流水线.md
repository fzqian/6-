# 报告模板库 · 使用规范

> 这份文件的唯一目的：**让任何一个新会话，用新一批聊天记录，做出和 `output/web-report/index.html` 一模一样版式的报告。**
>
> 如果你是新接手的 AI：先读完这一页，再动手。不要自己设计样式，不要改板块顺序，不要跳过截图。
>
> **版式看本文件，判断看 `判断标准.md`。** 正文里每一句「好 / 不好」都要能在 `判断标准.md` 找到对应的标准；找不到标准就别下判断，改写成事实。

---

## 0. 为什么有这个东西

2026-11-09 出过一次事故：新会话照 `HANDOFF.md` 做报告，结果样式、板块位置、微信截图全部丢失。

原因不是能力问题，是 `HANDOFF.md` 里 `build_site.py` 被描述成"可复用的生成器"，实际它是**这一批数据的定制产物**——它用 `ast` 去解析 `build_docx_v16.py` 里的 `PROBLEMS`/`JUDGE` 变量，案例原文、判定口径全硬编码在 Python 源码里。新数据进来，那个脚本根本跑不起来，只能重写，版式自然就飞了。

所以把「版式」和「内容」拆开：

| 层 | 谁来定 | 在哪 |
| --- | --- | --- |
| **版式**（颜色、字号、间距、板块顺序、组件结构） | **固定，不许改** | `assets/style.css` + `assets/app.js` + `骨架.html` |
| **内容**（数据、案例、结论文字） | 每批次不同 | 填进 `骨架.html` 的占位处 |

---

## 0.5 怎么把这一套交给新窗口

**要交的是整个 `_report-kit` 文件夹，不是其中一两个文件。** `style.css` 缺了样式就全丢，`shot.py` 缺了就没图，`骨架.html` 缺了版式就重排。

新窗口开在同一台电脑上，直接发这一句（路径按实际改）：

> 读 `<本文件夹绝对路径>\README.md` 和 `<本文件夹绝对路径>\判断标准.md`，按 README 的四步流程做一份新报告。版式不许自己设计，`assets/style.css` 和 `assets/app.js` 原样复制不许改，五板块顺序不许改，每张案例卡必须有截图，正文的判断必须符合 `判断标准.md`，最后跑 `check.py` 直到十项全过（第 10 项查「正文引号是否都能在对应截图上找到」）。聊天记录在 `<把文件夹路径贴这里>`。

实际发出来长这样：

> 读 `C:\Users\admin\Desktop\体德报告套件\README.md` 和 `C:\Users\admin\Desktop\体德报告套件\判断标准.md`，按 README 的四步流程做一份新报告。版式不许自己设计，`assets/style.css` 和 `assets/app.js` 原样复制不许改，五板块顺序不许改，每张案例卡必须有截图，正文的判断必须符合 `判断标准.md`，最后跑 `check.py --data dialogs_all.json` 直到十项全过（第 10 项：正文每个「」都要能在同卡片那张截图上找到）。聊天记录在 `C:\Users\admin\Desktop\体德聊天记录汇总\02_按客户拆分`

聊天记录有两种格式能用，先认清楚手里是哪一种：

| 手里是什么 | 用什么解析 | 识别特征 |
|---|---|---|
| 电脑版微信「导出聊天记录」txt | `to_dialogs.py` | 内容是 `·昵称` / `2026年9月14日 22:56` / 正文 |
| 企微后台「会话存档 / 会话消息」xlsx | `xlsx2dialogs.py` | 一条消息一行，10 列，有「发送人身份」列 |

- 微信里「合并转发」给别人的那种多选消息，粘出来**没有时间戳**，`to_dialogs.py` 不认，别用。
- 直接把文件拖进对话，或者放一个文件夹里给路径，都行。放文件夹更稳，`to_dialogs.py` 是这个用法。
- **xlsx 一步就够**，不用先转 txt。如果这份 xlsx 是按员工导出的，它打包的是**这个员工名下所有客户**，不是一位客户——见 §5 第 8 条。

放法（和现在这批一样）：

```
桌面\体德聊天记录汇总\
├── 01_原始导出文件\   微信直接导出的 txt，一个销售一个文件
└── 02_按客户拆分\     拆好的，一个客户一个文件，开头有 # 销售 / # 客户
```

`to_dialogs.py` 两个目录都能吃。有 `02_按客户拆分` 就用它，更准。

### 0.6 动手前先认批次（30 秒，决定 PART 03 写什么）

| 数据长什么样 | 批次性质 | PART 03 用什么维度 |
|---|---|---|
| 20+ 个 txt，每个一位客户 | 全团队多销售 | 六阶段漏斗 |
| 一份 xlsx，里面 40+ 个会话 | 单销售多客户 | 六层客户纵深 |
| 1–2 个 txt，一个客户上千条、跨两三个月 | 单客户跨月份 | 按日消息量分布 |

认错了不会报错，只会写出一份「版式对、内容对不上」的报告。判断方法：解析完看「N 组 / N 条」——组数是 1，就是单客户；组数 40+ 且销售只有一两个人，就是单销售。

## 2. 标准流程（四步）

### 第 1 步 · 数据进 JSON

```bash
cd output/_report-kit
python to_dialogs.py "C:/Users/admin/Desktop/体德聊天记录汇总/02_按客户拆分" --out dialogs_all.json
```

- 输入目录里放 `02_按客户拆分` 风格的 txt（带 `# 销售 / # 客户` 文件头最好），也吃 `01_原始导出文件` 那种不带头的。
- 会打印「文件 N 个 → N 组 / N 条消息」，**先看这个数字对不对**（37 组 5306 条是基线）。
- 同（销售,客户）跨文件自动合并去重。
- 输出目录不存在会自动创建，不用先 mkdir。

**手里是企微导出的 xlsx 就用另一个解析器**（一条消息一行，10 列）：

```bash
python xlsx2dialogs.py --xlsx "会话消息.xlsx" --out dialogs_all.json
# 多份合并：--xlsx a.xlsx --xlsx b.xlsx
```

它替你处理掉三件事：① 行序是倒的，转正序 ② 时间 `2026-11-08 20:45:41` 转成 `2026年11月8日 20:45`（不补零）③ 引用回复被拼进正文（`“某人：\n原话”\n------\n回复`），压成一行 `（引“原话”）回复正文`。

xlsx 比 txt 更好的地方：**有独立的「发送人身份」列**，不用靠昵称猜谁是谁——txt 那套曾因为销售改了别名，把 33 条消息当成客户消息剔掉。字段对照见 §7。

### 第 2 步 · 出截图

```bash
# 先看有哪些客户
python shot.py --list

# 截一段
python shot.py --cust "@平静" --start "湖南长沙位置" --end "没问题的" \
    --id C30_P1 --note "客户主动要到校区，销售只回「你跟我说时间就好」" \
    --out ../web-report/assets/prob

# 截多段（段间自动出现「—— 间隔 N 天 ——」）
python shot.py --cust "Atopos" \
    --seg "一万九到两位六区间|看看在不在的预算范围内" \
    --seg "如果超出预算的话选择一个最基础的新国职|这个是无价的" \
    --id C38_P3 --out ../web-report/assets/prob
```

**数据源必须盯住。** `shot.py` 会打印「数据：路径（N 组，生成于 时间）」。默认顺序是「本目录 `dialogs_all.json`」→「`../brief-compose/dialogs_all.json`」，后者是**上一批的旧数据**，一旦命中会打 ⚠ 警告。看到 ⚠ 就是数据源错了，加 `--data` 指到本批 json，否则截出来的是旧对话，而客户昵称可能对得上、只差一两条，肉眼看不出来。

产物是 440px 宽（问题点）／440px 宽（节奏、片段）的微信风格 PNG，绿气泡在右（销售）、白气泡在左（客户），底部带琥珀色标注。

**出门两张，一张图一个 .json。** `shot.py` 除了 PNG，还会在同目录写一个同名 `.json` 侧写，记录这张图**实际渲染了哪几条原文**。这不是备份，是第 4 步核对的凭据：正文里每一个「」，都要能在这个侧写里找到。它由脚本自动生成，不要手写、不要手工改，重跑一次图就同步了。

**每张图必须让读者看见「客户问了什么」。** 这是对照表里最容易犯的错：只截销售那段回复，图上全是绿气泡，读者不知道他在回答谁。`shot.py` 默认 `--lead auto`，会从 `--start` 往上回溯，命中第一条客户消息就把它一起截进来，并在顶部标「—— 以上省略 ——」；起始句本身就是客户说的，则不再往上堆。

跑完看这行输出，出现 `!` 就说明这张图还是没客户消息，必须改：

```
! 这张图里一条客户消息都没有，读者看不到「客户问了什么」。
```

两种修法：

| 情况 | 做法 |
| --- | --- |
| 客户那句话就在前面几条 | 默认的 `--lead auto` 已经处理；不够就把 `--lead` 调大，或直接把 `--start` 换成客户那句原话 |
| 客户问完隔了几天才回 | **必须用 `--seg` 拆两段**，让图里自然出现「—— 间隔 2 天 ——」。不能只截后面那段 |

还有一个反过来的坑：`--start` 写销售那句、前因又在两天前，硬塞进一张图会变成 1800px 长的巨图，而报告里 `.case-shot` 只露 200px——关键内容全在折叠区外。**起始句优先选客户的原话**，这样折叠预览第一眼就是客户在问什么。

**三个图类目录，不要混：**

| 目录 | 用在哪 | 命名 | 数量（基线） |
| --- | --- | --- | --- |
| `assets/prob/` | PART 02 每个问题点案例 | `C30_P1.png` = 案例号_问题点名 | 23（37 组基线） |
| `assets/stage/` | PART 03 四种典型节奏 | `r1_zhibao.png` | 4 |
| `assets/good/` | PART 04 每段正面标杆 | `q1.png` ~ `q8.png` | 8 |

数量是基线，不是指标。数据少的批次自然少图：画我组（1 组 1372 条）16 张（prob 6 / stage 4 / good 6），子渝（48 组）14 张（prob 4 / stage 4 / good 6）。**但五个板块每块都必须有图，一块都不能空着。**

### 第 3 步 · 照骨架填内容

复制 `骨架.html` → 五板块逐个替换。**结构一个 div 都不要动**，只改文字、数字、`src` 图片名、`data-zoom` 标题。

替换顺序建议：封面 → PART 01 → PART 03（表最机械，先做）→ PART 02 → PART 04 → PART 05。

**填文字前先读 `判断标准.md` 和 §8。** 版式可以照抄，结论不行——每批数据的断点、主要问题都可能完全不同，套上一批的结论是这份工作最容易犯的错。

### 第 4 步 · 交付前自检

```bash
python check.py ../web-report/index.html
```

十项自动查：板块顺序、导航锚点、图片是否存在、`data-zoom`、占位符残留、`style.css` 是否被改、`app.js` 是否被改、版本号、class 是否都有定义、**正文引语是否都能在对应截图上找到**。

```bash
python check.py ../web-report/index.html --data dialogs_all.json
```

`--data` 给的是第 1 步产出的那份对话 json，第 10 项靠它区分两种错：

| 报错 | 含义 | 怎么改 |
|---|---|---|
| ✗A 原文里有、这张图没截到 | 正文按整组故事线写，截图只截了一段 | 把 `--start/--end` 扩到那句，或改成多段 `--seg`；实在不该进图就删掉这句 |
| ✗B 原文里也没有 | 引号里写成了概括（「500 订金膨胀 2000」这类） | 换成原话，或去掉引号改成叙述 |

**必须看到 `15 项全部通过` 才能交付。** 有 ✗ 就逐条改，别解释、别跳过。没给 `--data` 也能跑，只是两种错分不开，全按 ✗B 报。

机器查不了的两项，人补：

- [ ] 宽屏 1400px 看一遍：没有横向滚动条、没有文字溢出、截图没被拉变形
- [ ] 手机 390px 看一遍：`body` 已设 `overflow-x:hidden`，所以不会出滚动条，但**模板是桌面优先，390px 下正文右侧会被裁掉**——真品 `web-report` 同样如此，属已知行为，不算缺陷。窄屏只需确认「没有图片变形、没有元素重叠错位」即可
- [ ] 页脚数字（组数、条数、截张数、片段数）和正文一致

## 2.5 交付目录与顶部概要条（强制）

**报告不能只交一个 `index.html`。** 底稿要和报告放在同一个文件夹里，打开页面就能顺着链接查到原始那一行。目录名固定，编号不要改（顶部概要条的链接写死在这四个目录上）：

```
<报告名>/
├── index.html
├── assets/{style.css, app.js, prob/, stage/, good/}
├── 00_数据来源说明.md      原始文件哈希 / 行数 / 剔除规则 / 每个数字怎么复核
├── 01_原始导出/            原始 xlsx（或 txt），一个字节都不要改
├── 02_过程文件/            dialogs_*.json、facts.json、table.json、渲染片段
├── 03_依据文件/            六阶段参考场景、参考话术、判断标准.md
└── 04_流水线/              README、骨架.html、xlsx2dialogs / shot / check / check_quotes
```

**页面最顶部（`<body>` 第一个元素，`<nav>` 之前）必须有一条概要带**，两行，结构固定：

| 行 | 内容 |
| --- | --- |
| 第一行 | `报告名　销售/批次` ＋ `数据` 小标签 ＋ 导出渠道 / 条数 / 会话数 / 快照号 / 清洗后组数 |
| 第二行 | `依据` 小标签 ＋ 用到的文件名（书名号列出）＋ `底稿` 小标签 ＋ 00 / 01 / 02 / 04 四个链接 |

写这条的三个作用，别省：

1. 谁拿到都先在 30 秒内判断这批数据够不够新；
2. 结论有异议时，直接点到 `01_原始导出/` 对原始行，不用回来问；
3. 快照号（如 `261109_0947_47985`）一写，下一批数据和这一批不会串。

`check.py` 第 11 项会查：`.prov` 存在、含「数据」「依据」两个字样、至少 2 个底稿链接且**指向的路径真实存在**（写空链接会 ✗）。样式类名固定为 `.prov` / `.prov-in` / `.seg` / `.nb` / `<em>` 标签，已在 `style.css` 里定义好，直接抄 `骨架.html` 顶部那段即可，不要自己另造。

## 3. 五个板块的固定结构

**顺序不可调换。** 这是"先诊断、再立标杆、最后给动作"的叙事，换顺序读者会跟不上。

| # | id | 标题格式 | 必须包含 |
| --- | --- | --- | --- |
| 01 | `overview` | `PART 01 / 方法` | 3 张 `.method .card`（判断三问）+ `.revoke` 撤销说明（没有撤销就整块删） |
| 02 | `problems` | `PART 02 / 问题点` | `.dist` 条形图（按组数降序）+ `.plist` 问题点卡（判定口径 + N 个案例，每案例左文字右截图） |
| 03 | `rhythm` | `PART 03 / 谈单节奏` | `.stages` 六阶段 + `.funnel` 累计漏斗 + `.concl` 3 张结论卡 + 明细表 + `.rcases` 4 组典型 |
| 04 | `good` | `PART 04 / 正面标杆` | `.qfun` 筛选漏斗四步 + 入选标准说明 + `.qcard` 片段卡（每张配截图） |
| 05 | `actions` | `PART 05 / 落地` | `.acts` 建议卡（按问题点编号归并）+ `.endnote` 声明 |

### 片段卡内部顺序也固定

`发生了什么` → `做了哪几件事`（①②③编号）→ `为什么有效` → `同一场景，没这么做的那组`（红色 `.qopp`）→ `可以直接抄走的原话`（绿色 `.qreuse`）

这个顺序是"事实 → 动作 → 机制 → 对照 → 可复制"，缺任何一块，价值传递就变成了读后感。

### 批次不同，PART 03 / 04 的维度可以换（但 DOM 不变）

板块数、顺序、内部结构恒定；**看什么维度，按批次性质换**：

| 批次性质 | PART 03 看什么 | PART 04 标题 | 说明 |
|---|---|---|---|
| 全团队多销售（37 组基线这类） | 六阶段漏斗 + 最远到达分布 | 正面标杆 | 横向比人，看谁在哪一层掉 |
| **单销售多客户**（一位老师的整盘 xlsx） | **六层客户纵深**（L1–L6 累计）+ 消息量分布 | 优秀片段 / 标杆动作 | 没有横向可比对象，改成纵向看客户被推到哪 |
| **单客户跨月份**（一位客户 1000+ 条、两三个月） | **按日消息量分布**（哪几天聊了多少条） | 优秀片段 | 没有组数可比、没有客户可比，只能看时间轴 |

单销售批次的实测写法（子渝 48 组）：

- PART 03 标题 `PART 03 / 纵深分布`，用 `.stages` 摆六层、`.funnel` 摆累计人数、`.concl` 写断点结论，明细表换成 48 行「客户 × 到达层 × 关键动作」
- PART 02 的横条图从「按组数排序」改「按出现组数降序」，并在标题里写明分母（48 组）
- PART 04 每段必须带**同一场景下没这么做的对照**——单销售没有别的销售可比，就跟他自己的另一组比

单客户批次的实测写法（画我组 1 组 1372 条、跨 60 天）：

- PART 02 横条图改「该问题点首次出现在第几天」（32/32/36/36/48/50 天）——单组没有「多少组有这个问题」，只有「聊到第几天才出现」
- PART 03 漏斗改「按日消息量分布」，实测 4.13 一天 416 条占 30%，6 天吃掉 72% 消息——**说明这个客户是"两天热度"型，不是慢慢磨的**
- PART 04 每一段都要能对到具体日期和钟点，例：「最好的与最差的竞品处理只隔 8 分钟（13:30 vs 13:36）」

**换维度可以，换 DOM 不行。** `.stages` `.funnel` `.concl` `.tbl-wrap` `.rcases` 这几个容器不能删、不能挪位，`check.py` 第 1、9 项会拦。

## 4. 硬规则（违反即返工）

1. **不许自己写 CSS。** 不许新建 `<style>`，不许改 `style.css`。要调整只能通过已有的 class 组合。
2. **不许改板块顺序，不许合并板块。** 五块缺一不可——即使这一批数据里某块内容很少，也要保留结构并在正文写明「本批无」。
3. **不许省略截图。** 每张案例卡、每段正面标杆、每组典型节奏都必须有图。没图就说明还没做完，不是"简化版"。
4. **销售名不许压成简称。** 显示完整微信备注名（如 `体德陈老师（广州 长沙 南京）`），只有图表轴位置才允许用简称。
5. **不许给销售打总分。** 这份报告只讲动作和事实，分数容易吵，动作不会。
6. **截图必须是原文渲染，不许改写、不许美化、不许"大概意思"。** `shot.py` 是从 `dialogs_all.json` 直接渲染的，保真。
7. **每个判断都要能在 `判断标准.md` 找到依据。** 找不到依据的判断，改写成事实（时间 + 原话），不要写成评价。
8. **不许写数不出分母的百分比。** 每一个比例都要当场能数出来；数不出来就写绝对数（「17 组」而不是「46%」）。
9. **不许拿上一批的结论套新数据。** 断点、主要问题、失败型分布每批都可能不同，必须从这批数据重新算。
10. **正文里每个「」，都必须是客户或销售的原话，而且必须出现在同一张卡片右侧那张截图上。** 这是最隐蔽的一类错：正文写「客户回了：那就差不多 3 万块」，图却停在上一句 28700——读的人一眼找不着，整张卡就废了。三条推论：
    - 概念性表述（「你的产品矩阵长什么样」「他不想被通知一个总数」）**不要加引号**，改成 `<b>` 或直接叙述；
    - 摘要式引语（「500 订金膨胀 2000」）不算原话，要写成原文 `「500元订金，新国职和ACE，可以膨胀到2000元」`；
    - 引用另一位客户（`.qopp` 对照段）不受这条约束，但要写明「（见 PART 02 · Px）」，让读者能跳过去核。
11. **不许编造——引号外也一样。** 第 10 条管的是「」，可 2026-11-09 真出过的事故是不带引号的那种：片段六写「他说清了它不擅长什么（运动科学这块讲得相对浅一点）」，完达山 113 条里根本没这句，是写的人从行业常识补的。**带引号的错是抄错，不带引号的错是编造。** 三条落地：
    - **具体信息必须落到原文**：金额、日期、几点几分、证书名/品牌名/校区名、括号和破折号后面那半句，都要能在这一组的原始消息里指出来。
    - **别组的数字不许搬进这组**：一个是真的、但放错位置的数字，比一个明显的错更难被读者发现。
    - **写完自查一遍**：把每句「他说了什么」拆成关键词，在 xlsx 里搜；搜不到，要么改成原话，要么删。`check.py` 第 12 项（`audit_claims.py`）能机器核金额 / 日期 / 时间点 / 外文词和括号补语，中文定性描述机器核不了，只能人过。

## 5. 已知的数据坑

1. **名片残留**：导出文件末尾常有 `吴文增-18732365605` 这种联系人卡片，原 `dialogs_all.json`（5313 条）把它们当成了客户消息。`to_dialogs.py` 已剔除，所以新产出是 5306 条——**差 7 条不是丢数据**。
2. **正文可以 `#` 开头**：有一条消息是 `#体智德训就业推荐(长沙)`，早期版本误判成文件头导致整条丢失。`to_dialogs.py` 已修。
3. **`[图片]` `[语音]` 是占位符**，内容读不到。价目表、证书、课程表都在图里，纯文字分析看不到——报告里要如实说明这个盲区。
4. **`[语音] 35"` 带时长**，时长可统计，内容不可读。
5. **月日不补零**（`2026年8月7日`），`strptime` 用 `%Y年%m月%d日` 前要归一化。
6. **时间戳不能按字符串排。** 因为不补零，`2026年10月3日` 会排在 `2026年9月30日` 前面。两个解析器都已改成 `time_key()` 拆数字元组排序，`xlsx2dialogs.py` 还对 `msgs` 再排一次兜底。**别用 `sorted(..., key=lambda m: m["t"])`。**
7. **时间显示不能硬切片。** `m["t"][5:16]` 在 `2026年3月8日 11:07`（16 字）刚好，遇到 `2026年11月4日 09:55`（18 字）会把最后一位吃掉，显示成 `11:3`。已改为 `m["t"].split("年",1)[-1]`。凡是两位数月份/日全中招。
8. **一份企微 xlsx 往往不是一位客户。** 按员工导出会打包他名下整个客户盘，还会混进与主管的内部复盘、合作方对话。`xlsx2dialogs.py` 已按「会话信息」自动拆桶，并从「发送人」识别销售名再切客户名。
   - 内部复盘（销售 ↔ 主管）**必须单独存 `internal.json`，不计入任何客户比例**。它可以作旁证引用，但报告 endnote 要写明「不计入统计」，否则读者会以为 48 组里含内部对话。
   - 拆完先看打印的「N 组 / N 条」，一个销售 40–50 组属正常；如果只出 1 组，说明没拆开。
9. **合并转发壳里的时间不是聊天时间。** `[聊天记录]` 外层占位带的是转发时刻，解析时要剔除，否则时间跨度会整个错位。

## 7. 两种输入格式的字段对照

渲染器和报告只需要三样东西：**谁说的、什么时候、说了什么**。两种导出都能给，但给法不一样。

| 渲染器需要 | 微信「合并转发」txt | 企微会话 xlsx |
| --- | --- | --- |
| 谁说的（S/C） | ❌ 靠昵称和文件名头猜，改过别名就认错 | ✅ 独立列「发送人身份」（员工 / 客户） |
| 时间 | ⚠️ `2026年3月8日 11:07`，只到分钟，月日不补零 | ✅ `2026-11-08 20:45:41`，**到秒** |
| 正文 | ✅ 逐行 | ✅ 「会话内容」列 |
| 消息类型 | ⚠️ 只有 `[图片]` `[语音]` 占位符 | ⚠️ 同样只有 `[图片]` `[表情]` `[位置]` `[小程序]` 占位符 |
| 引用回复 | ❌ 没有 | ⚠️ 拼在正文里，需拆（脚本已处理） |
| 图片 / 语音实体 | ❌ 没有 | ❌ 没有 |
| 行序 | ✅ 正序 | ❌ 倒序，最新在最上面 |

两条结论：

1. **xlsx 比 txt 更适合做批量分析**，因为「发送人身份」是硬字段，不依赖昵称匹配。txt 那套曾因为销售把昵称改成 `体德阿睿老师（广州 长沙 南京）`，把 33 条本人消息当成别人发的剔掉。
2. **两种格式都缺图片和语音的实体内容**。价目表、证书样张、课程表都在图里，纯文字分析看不见。报告里凡涉及这些，必须注明「截图未纳入分析」，不能推测图里写了什么。

## 8. 正文怎么写才算有内容

版式对了只是及格线。一份报告真不真，看正文能不能**点到原话**。五个板块各有一条硬要求：

| 板块 | 正文必须做到的 | 判断依据 |
|---|---|---|
| PART 01 方法 | 三张卡 = 判断三问，每问后面跟一句「本批怎么算的」 | `判断标准.md` §1 |
| PART 02 问题点 | 每个问题点给出**判定口径 + 出现组数 + 至少 1 个案例**，案例卡必须左右分工：左边说发生了什么，右边截图 | `判断标准.md` §7（易判错处） |
| PART 03 节奏 | 六阶段漏斗（单销售批次换成六层纵深）+ **断点在哪一跳 + 那一跳为什么掉**；断点每批不同，不许套用上一批结论 | `判断标准.md` §6 |
| PART 04 标杆 | 三条入选标准 + 每段五个固定块（缺对照段就是读后感）+ 漏斗数字可复算 | `判断标准.md` §十 |
| PART 05 落地 | 建议必须能对回 PART 02 的编号，一条建议对一个动作，不写「加强培训」这种没法验收的 | `判断标准.md` §5 |

**三条最容易写空的话，替换掉：**

- ✗「价值传递到位」→ ✓「他讲了 9 个月线上和两年复训，客户下一句开始问毕业能去哪」
- ✗「异议处理得当」→ ✓「客户说贵，他先问是钱紧还是怕学不会，客户说怕学不会，他才讲两年复训」
- ✗「节奏把握不好」→ ✓「客户 10.23 22:01 问石家庄有没有，他 10.27 10:30 才回，中间隔 3 天」

**判断不了就写事实，不要写评价。** 报告里所有评价句，都要能在同一段截图里找到对应的那一句原话。
